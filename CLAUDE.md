# Project Incubator - Claude Code Meta-Workspace

A deterministic system for transforming project ideas into complete, pre-seeded Claude Code workspaces through guided ideation and iteration.

**This is a GitHub TEMPLATE** - clone it for each new project to avoid context bleed between developments. Each clone becomes a dedicated workspace for one project. The output includes skills, commands, agents, hooks, and MCP configurations drawn from production-tested resource libraries.

## Purpose

This workspace helps non-coders develop project ideas into complete Claude Code project directories with:
- Comprehensive PRD documentation
- Pre-configured CLAUDE.md for the output project
- Appropriate skills, commands, and agents
- Human-readable documentation
- Clear "vibe coding" workflow

## How It Works

This is a **deterministic, gated workflow**. You cannot skip phases. Each phase has explicit completion criteria that must be validated before proceeding.

```
[BRAINDUMP] → CAPTURE → EXPAND → SPECIFY → ARCHITECT → CONFIGURE → SEED
```

Phase 0 (BRAINDUMP) is optional - use it when you have accumulated materials to process before starting.

## Template Usage

1. **Clone template** for new project: `gh repo create my-project --template Project-Incubator`
2. **Add brain dump materials** (optional): Put files in `braindump/` before initializing
3. **Run `/init my-project`**: Detects materials and routes to Phase 0 or Phase 1
4. **Work through phases**: BRAINDUMP → CAPTURE → EXPAND → SPECIFY → ARCHITECT → CONFIGURE → SEED

## The Phases

### Phase 0: BRAINDUMP (Optional)
**Goal**: Process accumulated materials before starting formal capture
**Input**: Unstructured notes, AI conversation transcripts, reference projects, voice memos, any brain dump materials
**Output**: Extracted insights + AI "dream" synthesis added to project seed
**Gate**: User confirms braindump processing is complete

This is a **two-part process**:

#### Part 1: Meta-Analysis
Process all brain dump materials to extract:
- **Explicit**: Directly stated ideas, goals, features, functionality
- **Implicit**: Unstated needs, underlying motivations, patterns across materials

Materials to process:
- Unstructured notes and thoughts
- AI conversation transcripts (Claude, ChatGPT, etc.)
- Reference projects or inspirations
- Voice memos or transcriptions
- Any accumulated "someday" notes

#### Part 2: Dream Phase
After meta-analysis, AI enters creative "dreaming" mode:
- Novel feature ideas inspired by the materials
- Unexpected connections between concepts
- Creative design possibilities
- "What if..." explorations

Uses `mcp__clear-thought__thoughtbox` with extended thinking for free-form ideation.

**Output stored in**: `braindump/`
- `extracted-insights.md` - Meta-analysis results
- `dream-synthesis.md` - AI creative exploration
- (Original files remain where you placed them)

**When to use Phase 0**:
- You've been collecting notes/thoughts about this idea for a while
- You have AI conversation transcripts discussing the concept
- You have reference projects or inspirations to analyze
- You want AI creative input before your own capture

**When to skip Phase 0**:
- Fresh idea with no accumulated materials
- You prefer to start with your own raw capture first

---

### Phase 1: CAPTURE
**Goal**: Get the raw idea out of your head into CONTEXT.md
**Input**: Voice notes, rambling thoughts, bullet points - anything
**Output**: CONTEXT.md with raw idea captured
**Gate**: CONTEXT.md exists and contains substantive content (>50 words)

**What to do**: Just dump your idea. Don't structure it. Talk about:
- What you want to build
- Why you want it
- Who it's for
- What problem it solves

### Phase 2: EXPAND
**Goal**: Systematically explore the idea from all angles
**Input**: Raw CONTEXT.md
**Output**: Expanded understanding via Socratic dialogue
**Gate**: All macro questions answered and documented

**Macro Questions** (must answer ALL):
1. Who is the primary user?
2. What is the core problem being solved?
3. What does success look like?
4. What are the 3-5 essential features?
5. What is explicitly OUT of scope?
6. What existing tools/workflows does this replace or complement?

**Clear Thought Integration**: Use `mcp__clear-thought__mental_models` with:
- `decomposition` - Break down the problem space
- `abstraction-laddering` - Move between "why" and "how"

### Phase 3: SPECIFY
**Goal**: Transform expanded understanding into structured PRD
**Input**: Completed expansion answers
**Output**: Versioned specification (spec/v1.md)
**Gate**: PRD passes completeness checklist (all sections present)

**PRD Structure**:
```markdown
# [Project Name] - Product Requirements Document

## Overview
- Problem statement
- Target user
- Success criteria

## Features
- Feature 1: Description, user story, acceptance criteria
- Feature 2: ...

## User Interaction Model
- How user interacts with the system
- Key workflows
- Input/output formats

## Constraints & Scope
- What's in scope
- What's explicitly out of scope
- Technical constraints
- Non-functional requirements

## Open Questions
- Decisions still needed
```

**Iteration**: Specs are versioned. v1 → v2 → v3 as you refine.

### Phase 4: ARCHITECT
**Goal**: Design technical implementation
**Input**: Validated PRD (spec/vN.md)
**Output**: Architecture decisions + tech stack
**Gate**: All architecture decisions documented with rationale

**Architecture Decisions**:
1. Project type (web app, CLI, workflow, etc.)
2. Tech stack (languages, frameworks, libraries)
3. Directory structure
4. Data model (if applicable)
5. External dependencies/APIs
6. Deployment model

**Clear Thought Integration**: Use `mcp__clear-thought__mental_models` with:
- `trade-off-matrix` - Compare tech stack options
- `pre-mortem` - Identify what could go wrong

### Phase 5: CONFIGURE
**Goal**: Determine Claude Code configuration for output project
**Input**: Architecture decisions
**Output**: Claude Code config specification
**Gate**: All config elements specified

**Config Elements**:
1. CLAUDE.md content for output project
2. Skills needed (from library or custom)
3. Commands needed
4. Agents needed
5. Hooks needed (if any)
6. MCP servers to recommend

### Phase 6: SEED
**Goal**: Generate the complete project directory
**Input**: All previous phase outputs
**Output**: Complete, ready-to-use Claude Code project
**Gate**: Project directory passes validation

**Output Structure**:
```
output/
├── CLAUDE.md           # Project instructions
├── CONTEXT.md          # Initialized with project context
├── README.md           # Human documentation
├── .claude/
│   ├── skills/         # Configured skills
│   ├── commands/       # Configured commands
│   └── agents/         # Configured agents
├── docs/
│   ├── PRD.md          # Final PRD
│   ├── ARCHITECTURE.md # Technical design
│   └── WORKFLOW.md     # Vibe coding guide
└── src/                # Scaffolded source structure
```

## Session Start Protocol (MANDATORY)

At the start of EVERY session, before any other work:

### 1. Check Living Idea Dump List in Notion

The **Living Idea Dump List** is a quick-capture tool for thoughts during active development. It's separate from the Phase 0 braindump - this is for ongoing ideas that come up while working on a project.

If Notion MCP is available, **always** check for new items:

```
Use mcp__notionApi__API-post-search with query: "[Project Name] Ideas" or "Idea Dump"
Use mcp__notionApi__API-get-block-children to retrieve items
```

### 2. Process New Items with User

If new items exist (status: ⏳ Pending):
- Present them to the user: "I found X new items in your idea list. Let's review them."
- For each item, discuss with user:
  - Is this still relevant?
  - Should this be integrated into current design/plan?
  - Should this be queued for a later phase?
  - Should this be declined?
- Update the idea dump list status (✅ Added, ❌ Declined, 🔄 Discussed)
- Integrate relevant items into CONTEXT.md, spec, or current phase work

### 3. Resume Normal Workflow

After processing any new ideas, continue with:
- Run `/status` to check current phase
- Resume work from where last session ended

### Why This Matters

The Living Idea Dump List is the user's external memory during active development. Ideas captured on mobile, during commutes, in the shower, or between sessions need a home. **Never skip this check** - these ideas represent the user's authentic, in-the-moment thinking that should inform the project.

### Living Idea Dump List vs Phase 0 Braindump

| Feature | Living Idea Dump List | Phase 0 Braindump |
|---------|----------------------|-------------------|
| **When** | During active development | Before starting (optional) |
| **Purpose** | Quick capture of new thoughts | Process accumulated materials |
| **Frequency** | Checked every session | One-time processing |
| **Content** | Brief ideas, feedback, features | Notes, transcripts, reference projects |
| **Processing** | Review & integrate | Meta-analysis + AI dream phase |

## ADHD-Optimized Workflow

This workspace incorporates ADHD-friendly design patterns:

### Working Style
- Break tasks into smallest possible steps (micro-chunking)
- Celebrate completions explicitly: "Got it! Nice work."
- Never shame for interruptions or restarts
- Default to voice-friendly short responses

### Session Management
- Use TodoWrite for ALL multi-step tasks
- Update persistent memory (Notion) in real-time
- Write handoff notes before context fills
- Welcome back warmly after breaks

### Guardrails
- No more than 3 parallel threads
- Always confirm before destructive operations
- Proactively remind about breaks after 90 minutes
- Clear visual progress indicators

### ADHD Challenge → Design Solution

| Challenge | Solution | Implementation |
|-----------|----------|----------------|
| Working Memory (3-5 items) | One action per prompt | Small scopes, TodoWrite |
| Time Blindness | Visual progress | `/status` command, phase indicators |
| Task Initiation | Obvious first step | Each phase has clear starter prompt |
| Dopamine Seeking | Immediate feedback | Celebration hooks in output projects |
| Object Permanence | Everything visible | Notion integration, CONTEXT.md |
| Context Switching | Minimal transitions | Gated phases, clear boundaries |

### Recommended MCP Servers for ADHD

| MCP | Why |
|-----|-----|
| **notionApi** | External brain, visible across sessions |
| **clear-thought** | Structured reasoning reduces cognitive load |
| **sequential-thinking** | Step-by-step without losing track |

## Notion as UI Layer

Notion serves as a friendly UI layer over Claude Code, providing async, phone-friendly interaction for users who find terminal-based Q&A difficult (especially with ADHD).

### The Three Roles of Notion

| Role | Purpose | Examples |
|------|---------|----------|
| **State Store** | Where project state lives | Ideation Canvas, Session Dashboard |
| **Input Channel** | User provides thoughtful responses | Input Forms, Living Idea Dump List |
| **Output Channel** | Claude communicates needs | Questions, Intent Confirmations |

### Notion Page Types

| Page Type | Purpose | When Created |
|-----------|---------|--------------|
| **Ideation Canvas** | Project state, progress tracking | `/new-project` |
| **Living Idea Dump List** | Quick thought capture during dev | Part of Ideation Canvas |
| **Input Form** | Structured questions needing thought | Session end (async) |
| **Intent Confirmation** | "Before I do X, confirm Y" | Complex/destructive actions |
| **Session Dashboard** | "Where was I? What's next?" | Auto-generated at session end |

### When to Use Input Forms vs Terminal

**Use Notion Input Forms when:**
- Questions require more than quick selection
- User benefits from time to think
- Multiple related questions build on each other
- Context/explanation helps understanding
- User is primarily mobile/phone-based
- Questions can wait until next session

**Use Terminal/Inline when:**
- Quick yes/no or A/B/C selection
- User is actively engaged in terminal
- Immediate response needed
- Simple clarification

### Input Form Workflow

1. **During session**: Claude identifies questions needing thought
2. **Session end**: Hook reminds Claude to create Input Forms in Notion
3. **Between sessions**: User answers forms on phone at their pace
4. **Session start**: Hook checks for completed forms
5. **Processing**: Claude integrates responses into project

### Intent Confirmation Workflow

Triggered when prompts contain:
- **Destructive keywords**: delete, remove, overwrite, reset, wipe
- **Broad scope**: "all files", "entire project", "everything"
- **Complexity**: >25 words with multiple clauses
- **Uncertainty**: Claude's confidence <80%

**For simple cases**: Inline terminal confirmation
**For complex cases**: Create Notion Intent Confirmation page

## Hooks Architecture

This workspace uses hooks for automation at key lifecycle points.

### Available Hooks

| Hook | Event | Purpose |
|------|-------|---------|
| `session-start.sh` | SessionStart | Load context, check Notion for pending items |
| `prompt-submit.sh` | UserPromptSubmit | Analyze prompt, check for intent confirmation needs |
| `session-end.sh` | Stop | Update Notion, create forms, store context |

### Session Start Hook

At session start, the hook:
1. Loads context from claude-mem (if installed)
2. Checks Living Idea Dump List for pending items (⏳)
3. Checks for completed Input Forms
4. Checks for pending Intent Confirmations
5. Outputs JSON summary for Claude to process

### Prompt Submit Hook

When user submits a prompt:
1. Analyzes complexity (word count, structure)
2. Checks for destructive keywords
3. Checks for broad scope indicators
4. Optionally runs through prompt-improver
5. Flags prompts needing confirmation

### Session End Hook

When session ends:
1. Reminds Claude to create Input Forms for pending questions
2. Prompts update of Session Dashboard
3. Stores context in claude-mem (if installed)
4. Logs session for continuity

### Hook Configuration

Add to `.claude/settings.json`:

```json
{
  "hooks": {
    "SessionStart": [
      {
        "matcher": "",
        "hooks": [
          {
            "type": "command",
            "command": ".claude/hooks/session-start.sh"
          }
        ]
      }
    ],
    "UserPromptSubmit": [
      {
        "matcher": "",
        "hooks": [
          {
            "type": "command",
            "command": ".claude/hooks/prompt-submit.sh"
          }
        ]
      }
    ],
    "Stop": [
      {
        "matcher": "",
        "hooks": [
          {
            "type": "command",
            "command": ".claude/hooks/session-end.sh"
          }
        ]
      }
    ]
  }
}
```
